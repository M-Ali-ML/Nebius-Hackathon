How it works

We read 100 scanned pages of the Encyclopaedia Britannica (6th and 7th editions, about 1820 to 1842), find the matching Wikipedia articles, and compare what each side says. Green steps use a Nemotron model.

  1. Parse 3.5 nvidia/nemotron-3.5-parse
    Reads each scan. Returns text blocks with class (Text, Section-header, Picture, Caption, ...), bounding box, and reading order. We keep the raw reply and build a LaTeX document per page from the blocks.
  2. Entries
    Rules split the page text into encyclopedia entries at uppercase headwords. Running heads give the topic of long treatise pages and continuations.
  3. BM25 search
    Searches 7.18 million English Wikipedia articles (fixed snapshot) with the headword and key terms. Returns the top 30 candidates with page and revision IDs.
  4. Embed VL nvidia/llama-nemotron-embed-vl-1b-v2
    Embeds the entry (query) and candidate excerpts (documents) as 2048-d vectors. Keeps the closest candidates by cosine. On plate pages it embeds the engraving image itself.
  5. Rerank VL nvidia/llama-nemotron-rerank-vl-1b-v2
    Scores each entry-candidate pair with a cross-encoder logit. A match needs a logit above the threshold and a clear margin; else the entry is marked "no clear counterpart". On plate pages it scores the plate image against each article.
  6. LanceDB
    Stores entries and Wikipedia chunks with their vectors, IDs, and checksums, so the agent can search both sides.
  7. Super VL compare nvidia/Nemotron-3.5-Super-VL
    Reads each matched pair. Lists similarities, differences, and claims, each with a quote from both sides. Tags each claim enduring, renamed, superseded, or dropped. We reject any quote that is not an exact substring of its source. On plates it describes the engraving and proposes search terms.
  8. Hermes agent Super VL as the reasoning model
    Answers questions with three tools: search_sources (LanceDB + Rerank VL), get_pair (saved comparison), and view_scan (image crop of the original page). Answers cite [B:row:n] and [W:page_id:revision].

Rules we keep

  • Source text is shown as Parse returned it. We do not correct OCR.
  • Generated content is marked in blue; source data in beige.
  • Failed model calls are logged, not replaced.
  • Every match keeps the scan checksum and the Wikipedia revision ID.
